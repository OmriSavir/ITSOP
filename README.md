# ITSOP: Prediction Optimization of Interrelated Time Series

Code accompanying the anonymous submission "ITSOP: Prediction Optimization of Interrelated Time Series." This repository implements the full pipeline described in the paper: candidate-model grid search, feature extraction, the ITSOP matrix-completion methods (MLP with one-hot inputs, MLP with time-series features, and the nuclear-norm M-estimator), the model-selection baselines (FFORMS, AutoForecast, Random@K, validation oracle), and the sample-complexity / rank-incoherence / statistical-significance analysis.

## Repository structure

```
itsop/
├── data_preparation/
│   └── covid19/                  # builds the COVID-19 dataset from raw CSVs
├── grid_search/                  # computes the validation-loss matrix per dataset
├── test_forecasting/             # generates test-period forecasts for every candidate model
├── feature_extraction/           # tsfresh / catch22 feature extraction per dataset
├── baselines/                    # FFORMS, AutoForecast, Random@K, validation oracle
├── itsop/                        # MLP (one-hot), MLP (with features), M-estimator
├── analysis/
│   ├── rank_incoherence_estimation.py     # rank / incoherence estimation (all 3 datasets)
│   └── statistical_significance.py        # significance testing on MLP vs. M-estimator sMAPE
├── scripts/                      # wrapper scripts that run each dataset's full pipeline
├── logs/                         # not included — manually generated, see below
└── data/
    ├── covid19/raw/              # included
    ├── snp500/                   # included
    └── electricity/              # not included (proprietary — see below)
```

## Datasets

The COVID-19 and S&P 500 datasets are public and included in this repository under `data/`.

The electricity-consumption dataset is proprietary and cannot be publicly released. To run the electricity pipeline, place the following files manually in `data/electricity/` before running anything:
- `consumption_dataset.pkl`
- `electricity_feature_extraction_catch22.pkl` (must contain a `city_Electricity` column)

**Note:** `feature_extraction/electricity_feature_extraction.py` also produces a file with the exact same name, `electricity_feature_extraction_catch22.pkl`, but writes it by default to `outputs/electricity/` rather than `data/electricity/`, and with a different schema (no `city_Electricity` column). These are two distinct files that happen to share a name — do not confuse the manually-supplied input file with the one generated by the pipeline.

```bash
bash scripts/00_install_dependencies.sh
```

`cvxpy` is used with the SCS solver for the M-estimator.

## Before running: the DATASET variable

Seven scripts each hardcode the dataset they operate on via a `DATASET = "covid19"` variable near the top of the file:

```
baselines/autoforecast.py
baselines/fforms.py
baselines/random_k.py
baselines/validation_oracle.py
itsop/mlp_onehot.py
itsop/mlp_features.py
itsop/m_estimator.py
```

Command-line flags (`--data-dir`, `--output-dir`, etc.) only control *where* files are read from and written to — they do not select the dataset. To run any of these seven scripts on `snp500` or `electricity`, edit the `DATASET =` line in that file first. Forgetting this will not raise an error; the script will simply run again on covid19.

`autoforecast.py` and `fforms.py` also have a `MODEL_TYPE = "all"` variable, which should generally be left as `"all"`.

`analysis/rank_incoherence_estimation.py` is the only script that handles all three datasets automatically in a single run.

## Statistical significance testing

`analysis/statistical_significance.py` runs a Friedman omnibus test followed by pairwise Wilcoxon signed-rank tests with Holm correction on the repeated sMAPE results (10 repetitions × 5 sampling budgets — 0.2/0.5/1.0/2.0/5.0·B0) of two ITSOP methods, MLP (one-hot) and the M-estimator, across all three datasets. It does not include `mlp_features`.

Unlike every other analysis script in this repository, it does not read directly from the pipeline's `.pkl` outputs. Instead, it reads **6 plain-text log files** that must be generated manually beforehand by redirecting the stdout of `itsop/mlp_onehot.py` and `itsop/m_estimator.py` to a file, once per dataset (editing `DATASET =` between runs, exactly as for the baselines/itsop stage):

```bash
mkdir -p logs

python itsop/mlp_onehot.py > logs/covid19_mlp_vanilla_all_models.log
python itsop/m_estimator.py > logs/covid19_m_estimator_all_models.log

# edit DATASET = "snp500" in both files, then:
python itsop/mlp_onehot.py > logs/snp500_mlp_vanilla_all_models.log
python itsop/m_estimator.py > logs/snp500_m_estimator_all_models.log

# edit DATASET = "electricity" in both files, then:
python itsop/mlp_onehot.py > logs/electricity_mlp_vanilla_all_models.log
python itsop/m_estimator.py > logs/electricity_m_estimator_all_models.log
```

Once all six log files exist:

```bash
python analysis/statistical_significance.py --logs-dir ./logs
```

`--logs-dir` defaults to `./logs`. The expected file names are fixed and must match exactly:

```
covid19_mlp_vanilla_all_models.log
covid19_m_estimator_all_models.log
snp500_mlp_vanilla_all_models.log
snp500_m_estimator_all_models.log
electricity_mlp_vanilla_all_models.log
electricity_m_estimator_all_models.log
```

No wrapper script is currently provided for this step (unlike `scripts/01`–`04`) — the six runs above must be done manually.

## Pipeline order

```
grid_search/  ──┬──> test_forecasting/  ──┐
                │                          │
                └──> feature_extraction/ ──┼──> baselines/  ──┐
                                            │                  │
                                            └──> itsop/  ──────┴──> statistical_significance.py
                                                                   (via manual log files, see above)

grid_search/ (all three datasets) ─────> analysis/rank_incoherence_estimation.py
```

1. **Step 0** (covid19 only): `data_preparation/covid19/create_dataset.py`
2. **Step 1**: `grid_search/*` — one script per dataset, independent of each other
3. **Step 2a**: `test_forecasting/*` — requires step 1 for the same dataset
4. **Step 2b**: `feature_extraction/*` — requires step 1 for the same dataset; can run in parallel with step 2a
5. **Step 3**: `baselines/*` and `itsop/*` — require steps 1 and 2a for the same dataset; `autoforecast.py` and `mlp_features.py` additionally require step 2b; `fforms.py` computes its own features internally
6. **Step 4**: `analysis/rank_incoherence_estimation.py` — requires step 1 for all three datasets
7. **Step 5**: `analysis/statistical_significance.py` — requires `itsop/mlp_onehot.py` and `itsop/m_estimator.py` (step 3) to have been run for all three datasets, with their stdout captured to the six log files described above. Independent of step 4 — neither depends on the other.

## Running the pipeline

The `scripts/` directory wraps each dataset's full pipeline in a single command, run from anywhere in the repository:

```bash
# --- COVID-19 --- (data already included, DATASET="covid19" is already the default)
bash scripts/01_run_covid19.sh

# --- S&P 500 --- (data already included)
# Edit DATASET = "snp500" in the 7 files listed above first, then:
bash scripts/02_run_snp500.sh

# --- Electricity --- (proprietary data — see "Datasets" above)
# Edit DATASET = "electricity" in the 7 files listed above first, then:
bash scripts/03_run_electricity.sh

# --- Rank / incoherence analysis --- (requires grid_search to have run for all 3 datasets)
bash scripts/04_run_analysis.sh

# --- Statistical significance --- (requires the 6 manual log files described above)
python analysis/statistical_significance.py --logs-dir ./logs
```

`scripts/02_run_snp500.sh` and `scripts/03_run_electricity.sh` check that all seven files actually have the correct `DATASET =` value set before running the baselines/itsop stage, and abort with an explicit error if not.

Only `scripts/03_run_electricity.sh` accepts an optional data-directory argument (`bash scripts/03_run_electricity.sh /custom/path`), since the electricity dataset is not included in the repository and may need to be placed elsewhere. `01_run_covid19.sh` and `02_run_snp500.sh` do not take this argument — they always use the default data path, since both datasets are already included at that location.

To run individual scripts directly instead of through the wrappers, or to use a different data location for covid19/snp500, call them with explicit flags, e.g.:

```bash
python grid_search/covid19_grid_search.py --data-dir /path/to/covid_raw --output-dir /path/to/results
```

## Common pitfalls

- Running `test_forecasting/*` before `grid_search/*` for the same dataset → `FileNotFoundError` (missing `comb_to_id`).
- Running `autoforecast.py` or `mlp_features.py` before `feature_extraction/*` for the same dataset → error reading the tsfresh/catch22 file.
- For electricity: forgetting to place the two required files in `data/electricity/` beforehand — the wrapper script catches this with an explicit error; running the individual `.py` files directly will fail with a less informative `FileNotFoundError` partway through.
- Forgetting to update `DATASET =` before running on snp500 or electricity — the wrapper scripts in `scripts/` catch this and abort; running the individual `.py` files directly will not raise an error and will silently rerun on covid19.
- Running `analysis/rank_incoherence_estimation.py` before all three `grid_search` scripts have completed → `FileNotFoundError` on one of the matrices.
- Running `analysis/statistical_significance.py` before all six log files exist in `--logs-dir` → `FileNotFoundError`. Remember this step requires manually redirecting stdout from `itsop/mlp_onehot.py` and `itsop/m_estimator.py`, per dataset — it is not produced automatically by any other script.
